Glossary ​

The platform's vocabulary, one line per term. Each entry links to the page that explains it properly — start at core concepts for the five nouns that carry everything else.

The object model ​

TermIn one line
OrganizationThe top-level enterprise account: members, roles, rings, approval workflows, gate definitions, and policies all live here.
TenantA customer or business entity inside the organization, owning its testers, groups, and (usually) its applications; data is isolated per tenant by construction.
ApplicationA mobile app under management, registered with its bundle id (iOS) and/or package name (Android), owned by a tenant or organization-shared.
VersionA logical release-train of one application (7.12.0); carries one artifact per platform and freezes the moment any release references it.
ArtifactThe concrete immutable binary a tester installs — uploaded with provenance, validated through a seven-stage pipeline, identified by SHA-256.
ReleaseThe distribution event: one version's artifacts taken to a chosen audience through rings, approvals, and gates.
TesterThe person on the phone — linked to tenants, organized in groups, granted access to versions; uses only the Tester Portal.
Tester groupA named audience inside one tenant (Internal QA, Pilot, UAT) that narrows who a release targets.
EnvironmentAn organization-level deployment context (with versioned configuration) that a release can name — for example a staging or production context.

Access and identity ​

TermIn one line
MembershipThe link that makes a tester part of a tenant — without an active one, the tenant's apps and groups do not exist for them.
GrantPermission for a tester to see an application's builds: explicit per version, by application, by tag, or "latest N".
AuthorizationThe seven-layer decision chain that every API call and download runs; only an ALLOW mints a download.
Concealed denialThe rule that a denied caller gets the byte-identical 404 a genuine miss produces — existence is information, so refusals never hint.
Personal access token (PAT)The token that authenticates CLI and CI calls to the API; minted in the Console, shown exactly once.
SSOSigning in through your company's identity provider (OIDC or SAML) instead of email and password.
SCIMThe provisioning protocol that pushes joiners, movers, and leavers from the identity provider into ShipperDog automatically.
ABAC policyAn attribute-based access rule (DENY or REQUIRE) evaluated inside the authorization chain, usually for tenant or release scoping.

Deep dives: authorization · identity and SSO · the security model

Release governance ​

TermIn one line
RingA rung of the promotion ladder (engineering, internal, beta, production...); a release sits on exactly one ring and climbs one hop at a time.
PromotionThe act of widening a release to the next ring — evaluated against gates, approvals, eligibility, and policies before it commits.
PrecheckThe read-only command that runs the exact evaluation a promotion would run, returning the verdict and every blocker without writing anything.
Approval workflowThe named chain of roles (with ALL/ANY/conditional semantics) that a release must satisfy on its way through a ring.
Approval roundOne pass of the workflow's decisions on one release — satisfied, rejected, or restarted after rework.
GateA measurable release requirement (tests passed, coverage threshold, crash-free rate) whose failed or missing state blocks, fail-closed.
Evidence URLThe mandatory http(s) link a gate result carries — the report a human can follow; a gate without proof does not exist.
OverrideThe governed exception that stops a failed or data-less gate from blocking — exactly once, with a mandatory, audited reason.
Policy holdA named release-policy rule that pauses a crossing until an authorized person acknowledges it — a recorded human decision, not a silent pass.
ManifestThe frozen, immutable record of an approved release — what shipped, where it came from, and to whom it was targeted.
ProvenanceThe build facts captured at upload — commit, branch, pipeline, CI run URL, timestamp — so every artifact says where it was born.
RollbackThe ROLLED_BACK crossing that cuts a release's downloads at the moment of the crossing; the record is never erased.

Deep dives: rings and rollout · approvals and gates · rollback how-to

Distribution ​

TermIn one line
Rollout (staged)A plan that widens a release's audience in stages — percentages or explicit tenant sets — each stage advancing only on plan.
CohortThe deterministic set of tenants a rollout stage covers — the same plan on the same release always yields the same cohort.
Distribution channelAn external delivery rail (TestFlight, App Store, Google Play tracks, direct) a release dispatches through, with credentials bound per level.
Signed URLThe short-lived (minutes) download link the portal mints per tester per build — never a storage location, and it dies with the grant that minted it.
Telemetry tokenThe short-lived token a build carries when the team enabled telemetry — it lets the installed app report feedback and metrics without secrets.

Deep dives: staged rollout how-to · distribution channels · feedback and analytics

OTA updates ​

TermIn one line
OTA bundleA platform-agnostic self-applying archive (its own version row, signed at finalize with sha256 + Ed25519) an opted-in app downloads, verifies, and applies itself.
OTA releaseAn ordinary release on a ring whose distribution channel is ota, carrying exactly one bundle — approvals, gates, and history unchanged.
sdc1. app tokenThe per-application token embedded in a shipped app to authenticate the OTA check — an identifier, not a secret.
Rollout plan (OTA)The per-release ladder of cumulative stages that decides which devices see the update — RUNNING, PAUSED, HALTED, or COMPLETE.
Basis pointsA stage's threshold on a 10000-point scale; a device is admitted when its deterministic bucket (hash(deviceId, planSalt) mod 10000) falls under it.
HaltThe manual, audit-trailed stop of a rollout plan — alert rules notify, but never stop a rollout automatically.
Signing key (keyId)The app-scoped Ed25519 key behind ShipperDog's secret store whose public half and id ride the manifest for device-side verification.

Deep dives: OTA updates · feedback and analytics

Reading an error ​

TermIn one line
Fail-closedThe design rule that missing data blocks rather than passes — a gate with no result is a blocking gate, not a waived one.
Trace idThe short identifier an error toast shows when present; quoting it lets an administrator join your failure to the exact server-side events.
