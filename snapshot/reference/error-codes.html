Error codes ​

Every failure surfaces as a stable code. This page covers the codes a person actually sees — in a Console toast, a portal message, or CLI output — grouped by surface, with what it means and what to do. The complete registry, including codes only internal services and store-side connectors produce, lives in the developer registry.

How errors reach you ​

  • Console — a toast at the bottom of the screen: the code and the registry's one-line detail, with a trace id underneath. Quote the code and the trace id when you ask for help.
  • Tester Portal — a toast at the bottom of the screen, the same shape as the Console's: code, one-line detail, trace id.
  • CLI — the problem printed to your terminal plus a process exit code your pipeline can branch on.

Console ​

The codes an operator meets in day-to-day administration.

CodeWhat it meansWhat to do
INVALID_REQUESTA form or payload failed validation; the error names the offending field.Fix the named field and resubmit.
UNAUTHENTICATED / INVALID_TOKENYour session ended or the token is invalid.Sign in again.
FORBIDDENYou hold a role, but not the one this action demands.Check your role; ask an organization admin for the authority or have the right persona act.
*_NOT_FOUNDThe thing you addressed does not exist or you are not allowed to see it — refusals are deliberately indistinguishable (see troubleshooting).Verify the id; if it should exist, your access is the question — ask an administrator.
RATE_LIMITEDToo many requests; the answer carries a Retry-After hint.Wait the indicated time and retry.
MEMBER_EXISTS / *_TAKEN / *_EXISTSA uniqueness rule refused the write — name, email, bundle id, build number, or a definition that already exists.Choose a different name/value, or edit the existing entry instead of creating a twin.
LAST_ORG_ADMINThe last organization administrator cannot be removed.Grant admin to someone else first.
APPROVAL_SELF_APPROVALYou created this release, so you cannot approve it — whatever roles you hold.The named approver role decides; see approvals.
APPROVAL_ROLE_NOT_HELDThe step demands a role you do not hold; the error names the required role.Route the decision to a holder of that role.
APPROVAL_STEP_OUT_OF_ORDERSequential chains decide in order; this step is not the current one.Decide the current step first.
GATE_OVERRIDE_INVALIDOnly a failed or no-data gate can be overridden, exactly once.Check the gate's state; if it passed, no override is needed.
RELEASE_TRANSITION_*The lifecycle state machine refuses the crossing (illegal edge, missing reason).The error names the current and attempted states; use the legal edge shown on the release dashboard.
RELEASE_PROMOTION_BLOCKEDThe target ring's evaluation refused the hop; the error lists every blocker with evidence.Fix the blockers (or override a gate with a reason), then run the precheck and promote again.
RELEASE_PROMOTION_RING_SKIP / _RING_SPLIT / _RING_FINALThe hop is not one legal ring step (skip, split targets, or already final).Promote one ring at a time, per ring group; the final ring has no next hop.
ENVIRONMENT_DISABLEDA parked environment cannot be named by a new release.Reactivate the environment or choose another.
INTERNAL_ERRORSomething unexpected failed on the platform side; no internals leak.Retry once; if it repeats, report with the trace id.

Tester Portal ​

The codes a tester can meet — all of them are one screen away from a fix that is not yours.

CodeWhat it meansWhat to do
INVALID_INVITATIONThe invitation link is expired, already used, or mistyped — links are single-use and live seven days.Ask your team for a fresh invitation; see accept an invitation.
INVALID_CREDENTIALSEmail or password is wrong, or the account is locked or disabled.Re-check your password; if locked, ask your team.
INVALID_TOKENYour portal session ended while you were on a page.Sign in again — your place is kept in the app list.
DOWNLOAD_NOT_FOUNDThe download link lapsed (links live minutes) or the build was pulled / your access changed.Tap Download again for a fresh link; if it persists, the team pulled the build — see install on Android.
FEEDBACK_RELEASE_NOT_FOUNDThe feedback could not be attached to a release you are targeted by.Re-open the version page from your home screen and submit from there.
ATTACHMENT_REJECTEDAn attachment broke the rules — extension (png/jpg/mp4/txt/log), size, count, or a duplicate name.The error names the file; fix or drop it and resubmit.

CLI and CI ​

The codes the upload and release path prints (exit code 4) — the CLI reference covers the commands.

CodeWhat it meansWhat to do
ARTIFACT_FILE_TYPE_REJECTEDThe file is not an .ipa/.apk/.aab matching the declared platform.Check the extension and the --platform flag.
ARTIFACT_TOO_LARGEThe binary exceeds the upload ceiling; large files must use the resumable session path.Let the CLI take the session path (it does automatically past the threshold).
ARTIFACT_BUILD_TAKENThis version+platform already carries that build number.Bump the build number — artifacts are immutable, never overwritten.
UPLOAD_SESSION_EXPIREDThe resumable session timed out before finalize.Start a fresh upload.
ARTIFACT_NOT_VALIDATABLERevalidation applies only to a FAILED or still-VALIDATING artifact.Check the artifact's state first (artifact view).
VERSION_IMMUTABLEThe version's artifact set is frozen (terminal state or existing distribution).Cut a new version for new binaries.
APPLICATION_ARCHIVEDThe application is archived; no new versions, artifacts, or releases.An organization admin unarchives it, or you target another app.
RELEASE_ALREADY_EXISTSA release already exists for this application and version.Drive the existing one (release get).
RELEASE_TARGETS_INVALID / RELEASE_ARTIFACT_NOT_READYA target tenant/group does not hold the app, or a selected artifact is not READY.The error lists every offending entry; fix the set in one pass.
STORAGE_UNAVAILABLEObject storage refused the write; a retry is safe (a fresh id, never an overwrite).Retry the upload.
INGEST_WRITE_CONTENTIONThe telemetry batch collided with a concurrent write.Retry the batch — the SDK treats the Retry-After hint as advisory.

Inbound webhooks ​

Codes your CI system or store integration can see in receiver responses — uniform by design, so the response never hints which leg refused.

CodeWhat it meansWhat to do
WEBHOOK_SIGNATURE_REJECTED (401)A shared-secret delivery (GitHub, Jenkins, GitLab) failed authenticity — wrong secret, bad signature, stale timestamp, or no secret configured; the reason is uniform.Re-check the configured secret on both sides and the sender's clock; see webhooks.
WEBHOOK_DELIVERY_REJECTED (400)A store delivery (App Store, Google Play) failed provider verification.Re-check the provider's signed-token configuration.
WEBHOOK_PAYLOAD_MALFORMED (400)A verified sender's body was not readable JSON.Inspect what the provider actually posts.
WEBHOOK_PAYLOAD_TOO_LARGE (413)The delivery exceeds the payload ceiling (default 25 MB).Send payloads within the ceiling.

The one rule underneath

A denial never confirms existence: for every resource, "not found" and "not yours" are the same bytes. When a code surprises you, check troubleshooting before assuming a bug — and when reporting, always quote the trace id.
